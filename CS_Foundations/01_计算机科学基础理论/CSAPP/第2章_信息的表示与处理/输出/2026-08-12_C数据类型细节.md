# CSAPP 2.1 C 语言数据类型细节

---

## 一、整型默认符号规则与 char 特殊点

### 1. 通用默认规则

C 语言绝大部分整数类型，**默认都是有符号数**（可存储负数、0、正数）。只有手动添加关键字 `unsigned`，才会变为无符号整型（仅存储非负数）。

### 2. char 是标准例外（易踩坑）

- 实际主流编译器：默认将 `char` 视作**有符号 1 字节整数**
- C 语言官方标准：并未硬性规定 char 必须有符号，部分编译环境下 char 会是无符号
- 规范写法：如需稳定使用 1 字节有符号整数，必须显式书写 `signed char`
- 日常场景：多数字符存取场景下，char 有无符号不会影响程序运行逻辑

---

## 二、整型修饰词书写顺序

C 语言对 `unsigned`、`long`、`int` 修饰关键字的排列顺序无强制约束，`int` 关键字也可省略。以下四种声明含义完全一致：

```c
unsigned long
unsigned long int
long unsigned
long unsigned int
```

> 本书统一固定书写格式，规避写法混乱。

## 三、指针与浮点类型存储空间

### 1. 指针变量

指针（如 `char *`、`int *`）占用字节由系统架构决定：

- 32 位系统：指针占 4 字节
- 64 位系统：指针占 8 字节

### 2. 浮点类型

| 类型 | 名称 | 占用字节 |
|:----:|:----:|:--------:|
| float | 单精度浮点数 | 4 字节 |
| double | 双精度浮点数 | 8 字节 |

### 本段核心总结

1. 牢记整型默认有符号，char 符号属性不标准统一，严谨开发需用 `signed char`
2. 长无符号整型修饰词顺序可互换
3. 指针大小随系统位数变化，float、double 存储空间固定不变

## 四、补充发现：Windows 上 long 是 4 字节

### 推理过程

已知：CSAPP 表格说 64 位系统 long = 8 字节。但我跑 sizeof(long) 得到 4。为什么？

**推理步骤：**

1. 先确认系统位数：`sizeof(char *)` = 8，确认是 64 位系统
2. 但 sizeof(long) = 4，和 CSAPP 表格矛盾
3. 排除"这是 32 位系统"的可能（指针 = 8 已证伪）→ 结论：Windows 64 位 long 就是 4 字节

**为什么需要基准（指针大小）？**

看到 long = 4 时有两种可能：

| 可能 | 含义 | 后果 |
|------|------|------|
| A：这根本不是 64 位系统 | 32 位系统 long=4 完全合理 | 你没有发现任何新知识 |
| B：这是 64 位系统，但 long=4 | 课本和现实不一致 | 你发现了一个重要知识 |

指针大小的作用就是排除 A。`sizeof(char *)` = 8 唯一确定了当前是 64 位系统，锁定了变量，剩下的差异就是真正的知识。

### 根本原因：操作系统 ABI 不同

- **Linux (LP64)**：long 和 pointer 都是 8 字节
- **Windows (LLP64)**：只有 long long 和 pointer 是 8 字节，long 保持 4 字节

这是 ABI（应用程序二进制接口）的差异，不是编译器问题。Windows 上无论用 gcc 还是 MSVC，long 都是 4 字节——编译器必须遵守操作系统的 ABI，否则编译出的程序无法互相调用。

微软选择让 long 保持 4 字节，是为了兼容大量旧代码中 `sizeof(long) == sizeof(int)` 的假设。

### 经验

> 课本表格写的是 Linux 标准。写可移植代码时，永远不要假设 long 的大小。
